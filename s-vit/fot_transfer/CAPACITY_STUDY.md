# 独立的提示容量与零阶估计诊断

这项明文研究不修改原 FoT 或 91 参数模型，不读取官方测试集。`image9007` 是数量级对齐 BlackVIP 的自定义解码器，不是 BlackVIP 的复现，也没有 MPC 实现或 MPC 开销数据。

| 组件 | 参数数 |
|---|---:|
| 卷积 2→29，3×3，含偏置 | 551 |
| 卷积 29→29，3×3，含偏置 | 7,598 |
| 卷积 29→3，1×1，含偏置 | 90 |
| 可学习任务提示 3×16×16 | 768 |
| 合计 | 9,007 |

冻结的 MAE 和公开固定特征投影不计入可训练参数。此解码器使用 32 维特征和 GELU；与 BlackVIP 的 MAE 768 维特征、任务向量、五层解码器、数据和模型不同。结果应作为容量探索，不能称为对 BlackVIP 的等价复现。

`--mode audit` 在每个数据批次上计算同一损失的自动求导梯度，并比较 `--directions` 个正负扰动的有限差分与对应方向导数；记录相对 RMSE 和平均梯度方向余弦。有限差分与自动求导相近只能检查当前样本与数值步长，不能证明收敛或安全。高维随机方向的方向余弦小不必然表示实现有误。

`--mode train --optimizer zo` 支持 `image91` 和 `image9007` 的 q 个独立 Rademacher 方向；每次更新需要 2q 次骨干前向，q=1 的 `image91` 与现有训练采用相同单方向、更新中心和动量公式。`fot` 使用原 4 维单位球方向、原始 Adam 更新和 1 个方向。`--optimizer adam` 对同一提示结构提供明文一阶参照。

报告含数据和模型权重哈希，默认固定 1000 张分层验证图；`--val-samples 0` 可用完整验证集。每个 epoch 默认遍历所有三方训练样本一次，`--max-batches-per-epoch` 限定的短跑只用于调试。训练 loss 对零阶方法为扰动两次的平均，对一阶方法为当前参数损失，不是完全相同的指标。

当前 9,007 参数模型含标准明文 GeLU，还未设计或测量其安全协议，不可根据本实验推断 3PC 开销。与 BlackVIP 一样对齐参数数量不代表相同训练数据、骨干和训练预算；使用更多方向的开销要按前向次数一并报告。
